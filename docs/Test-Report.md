## 4. Стратегия

- **Функциональные модульные проверки.** Для каждой функции сравниваем результат с ответом, полученным из математической формулы независимо от реализации. Проверяем результат для целого и дробного аргумента, при нуле и вблизи нуля.
- **Техники чёрного ящика.** Используем классы эквивалентности и анализ граничных значений. Проверка масштабирования задаёт дополнительное математическое свойство — при увеличении размера втрое площадь растёт в девять раз, периметр в три.
- **Основной набор.** На функцию приходится 12 числовых сценариев, четыре проверки недопустимых вызовов, включая `None`, и проверка масштабирования. Для неправильных вызовов ожидается `TypeError` по сигнатуре или для неподходящего аргумента `None`. Ноль допускается как вырожденный случай.
- **Расширенный набор.** Ещё 14 сценариев на функцию проверяют предлагаемый контракт. Конечный отрицательный размер, `nan` и бесконечности должны давать `ValueError`, а строки, контейнеры, `bool` и комплексные числа — `TypeError`. Потеря диапазона при вычислении с `float` должна явно сообщаться через `OverflowError`, в том числе при округлении ненулевой площади до нуля. Точные целочисленные вычисления квадрата должны сохраняться. Это критерии данной серии проверок. Документация библиотеки их не задаёт.
- **Сравнение.** Целочисленные результаты и ноль сравниваются точно. Для остальных числовых результатов применяется `math.isclose` с `rel_tol=1e-12` и `abs_tol=0.0`. Положительный эталон (даже очень малый) тогда не считается равным нулю. Исключения сравниваются по типу. Записи вида `4×10^400` в таблице сокращают длинные целые числа.
- **Выполнение.** Сценарии подготовлены для ручного воспроизведения. Фактические результаты собраны отдельным прогоном прямых вызовов Python. Общая инструкция к строкам таблицы — открыть Python в корне репозитория, выполнить `import circle, square, math`, затем ввести выражение из колонки «Шаги воспроизведения». Если вызов выбросит исключение, записать его тип.
